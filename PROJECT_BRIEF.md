# Бриф проекта: To-Do List

Дата фиксации: 16 ноября 2026 года.

Этот файл хранит решения из обсуждения проекта. В разговоре с агентом его можно
называть «бриф проекта». Команда «сверься с брифом проекта» означает прочитать
этот файл перед дальнейшей работой. Новые явные указания пользователя важнее
записанных здесь решений.

## Цель и результат

Тестовое задание на позицию вайбкодера: создать аккуратный работающий список
задач с помощью AI-инструмента.

- Обязательный результат: ссылка на GitHub с кодом и короткое описание
  использованных AI-инструментов.
- Дополнительное преимущество: ссылка на публично доступный работающий сайт.
- Ориентир по сдаче, названный пользователем: 16–17 ноября 2026 года.
- Дополнительные пожелания работодателя к технологиям не сообщались.
- Пользователь уже работал с React.

## Обязательный функционал

1. Добавление задач.
2. Отметка выполнения и возврат задачи в активное состояние.
3. Удаление задач.
4. Сохранение данных после обновления страницы.

## Выбранный стек

- React.
- TypeScript.
- Vite для локальной разработки и сборки.
- Обычный CSS.
- localStorage для сохранения задач в браузере.

React выбран ради удобства разработки и знакомого пользователю компонентного
подхода. Чистый JavaScript обсуждали как достаточную альтернативу, но итоговый
выбор пользователя — удобство работы с React.

## Архитектура

Небольшое клиентское приложение. Используем встроенные хуки React.
Redux, Context, роутер, сервер и база данных для текущего объёма не нужны.
Не добавляем слои сервисов и репозиториев или универсальные абстракции на будущее.

```text
src/
├── components/
│   ├── TaskForm.tsx       # ввод и добавление
│   ├── TaskList.tsx       # список и пустое состояние
│   ├── TaskItem.tsx       # выполнение, редактирование и удаление
│   └── TaskFilters.tsx    # фильтры
├── hooks/
│   └── useTasks.ts        # состояние и действия с задачами
├── lib/
│   └── storage.ts         # чтение, проверка и запись localStorage
├── types.ts
├── App.tsx               # сборка интерфейса, выбранный фильтр
├── styles.css
└── main.tsx
```

- `useTasks` управляет задачами и вызывает модуль сохранения.
- `storage.ts` изолирует работу с localStorage и обработку ошибок.
- Фильтр хранится в `App`; видимый список и счётчики вычисляются из задач.
- Задача содержит `id: string`, `title: string`, `completed: boolean`.
- При изменении сохраняем список целиком; при загрузке проверяем формат данных.
- Данные локальны для браузера и адреса сайта, синхронизации между устройствами нет.

## Дизайн

Подтверждённое направление: дружелюбный светлый минимализм.
Воздух, чёткая типографика, мягкие скругления, спокойные цвета и один акцент.

Предложенная композиция: центральный блок со строкой добавления, фильтрами
и списком. Боковое меню не требуется для одного списка. Предложенный акцент — синий;
точную палитру и макет ещё предстоит выбрать.

Дизайн должен учитывать телефон, длинные названия, видимый фокус клавиатуры
и состояния «задач нет», «есть активные задачи», «всё выполнено».
Короткие анимации сопровождают действия пользователя.

Ориентир для дизайна: [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill).
Навык установлен и применён для рекомендаций по интерфейсу и React.
Конкретные решения и границы применения записаны в `DESIGN.md`.
frontend-design от Anthropic и Taste Skill рассматривались как альтернативы.

## Предложенные детали реализации

Эти дополнения реализованы в первой версии; они не являются требованиями работодателя:

- Добавление через Enter и кнопку, удаление пробелов по краям, запрет пустого ввода.
- Фильтры «Все / Активные / Выполненные» и счётчик оставшихся задач.
- Отмена удаления через уведомление.
- Сообщение, если сохранить данные не удалось.

Редактирование текста задач добавлено по последующей просьбе пользователя.
Сроки и категории остаются вне текущего объёма.

## Проверка и сдача

Проверить добавление, переключение выполнения, удаление и сохранение всех этих
изменений после перезагрузки. Если реализована отмена удаления, проверить и её.
Проверить мобильную вёрстку, длинные названия и управление с клавиатуры.

В README описать запуск, функционал, ограничения localStorage и фактическое
использование AI. Работа над проектом ведётся с Codex; другие AI-инструменты
указывать только при реальном использовании.

Реализация приложения готова. Для сдачи используется GitHub и публичная
демоверсия на GitHub Pages из ветки `gh-pages`. Сборка и браузерные проверки
выполняются локально перед публикацией. Настройка GitHub Actions не используется:
у текущего подключения GitHub нет разрешения `workflow`.
Ранее созданный Sites используется как дополнительный закрытый вариант публикации.

## Последующие уточнения

- Правки сначала показываем локально. Обновляем GitHub Pages и Sites только
  по явной команде пользователя на публикацию.
- Убрать слоган в шапке, солнце, подпись под заголовком, фразу «Чистый лист —
  хорошее начало», пояснение пустого списка и блок с предложениями задач.
- Текст блока прогресса и подсказки под формой описывает состояние и действие,
  без мотивационных слоганов. Подпись «Твой список» убрана.
- Для показа работы используем примеры в локальной вкладке и запись сценария.
  Не добавляем демонстрационные задачи автоматически каждому посетителю.
- Рядом с корзиной добавлен карандаш для редактирования названия. Enter или
  галочка сохраняет изменения, Escape или крестик отменяет. Пустое название
  не принимается; статус выполнения и позиция задачи сохраняются.
